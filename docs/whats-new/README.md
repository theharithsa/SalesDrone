# SalesDrone roadmap and release notes

[Roadmap](https://theharithsa.github.io/SalesDrone/roadmap.html) · [Release notes](https://theharithsa.github.io/SalesDrone/releases.html) · [Sprint Delivery](https://github.com/users/theharithsa/projects/4/views/10)

The public roadmap describes user outcomes and target windows. Update `roadmap.json` when a saved sprint or prerequisite changes. The public sequence is tenant isolation and SDR migration → invoicing pilot → signup decision. Maintenance items and decision records are tracked on the GitHub board.

The release archive combines a plain-language highlight in `releases.json` with each version’s full changelog entry. The public release date comes from the GitHub release’s publication timestamp in Asia/Kolkata. Verify the published release before adding that date. Changelog-only entries are identified separately. A candidate with a prepared highlight is marked as a changelog entry until publication is verified.

Run `npm run docs:build` and review the generated pages in `site/.build`. The diagram is rendered as HTML and CSS so the labels remain selectable, accessible and readable on phones. The optional product image uses an existing reviewed synthetic capture with its original version and hash. [Dynatrace release notes](https://docs.dynatrace.com/docs/whats-new/saas) informed the version index and distinction between upcoming and shipped work.
