# Shared lead work and scoped Assistant business reads

The phone header is shared by the full lead page and desktop inspector: company/Independent enquiry and a masked monospace tel link wrap at the available width. Invalid imported phone text is displayed literally without inventing a dial destination.

Lead Tasks now reads a bounded lead-scoped route rather than a recipient-filtered list. Current lead readers see responsibility; current lead editors can complete or reschedule Pending work, with expectedVersion and replay-safe UUID identity. Retitling/deletion and notification delivery retain their recipient rules. Private unlinked reminders are excluded. Two task indexes must be READY before Hosting is released.

The Assistant receives a static business dataset/field catalog, never arbitrary database credentials or a database dump. The server rechecks each source and paginated result against current membership, lead scope and independent import/report policy. Task, business and source epochs invalidate saved reads. Supported extra sources are shared lead tasks, notes, calls, transitions, import summaries, private owned Hygiene reports, Ready file metadata and current score views. File bodies, original workbook files, credentials, private chats and personal reminders remain outside the catalog. Structured scans use 100-row pages and explicitly report Partial at 25,000 physical source records. Qualitative insights continue to use the permission-filtered note RAG index when enabled; this release does not silently enable indexing.

Local browser review used fictional demo records. Completion changed the task to Completed and removed its Complete control. Rescheduling saved a new date/time and updated the card. Measured light viewports were 360x800, 390x500, 600x800, 768x900, 998x700, 1001x700, 1280x900 and 1920x900 CSS pixels, without document or shared-row horizontal overflow. Dark header checks include 390x500; a separate real-component fictional header at 125% app scale fit horizontally and scrolled vertically. Browser zoom was 70%, compensated and measured. Public captures were cropped only to remove the screenshot transport's right/bottom padding. This does not certify physical devices or Safari.

Regression coverage includes other-recipient lead-editor completion, read-only denial, terminal states, scope revocation, stable replay, personal-reminder exclusion, local calendar dates, multi-page 205-record counts, literal projection and source invalidation. Real Auth/Firestore emulator integration completed 11 cases including shared task completion/replay and Assistant retrieval. Synthetic live Gemini planner probes exercised open tasks by person, own calls, failed import rows, overdue work and file metadata. The file-metadata probe exposed an erroneous ownership restriction for “my leads”; server normalization and a regression now preserve the current accessible-lead scope. Model planning is still nondeterministic and unrecorded/unsupported facts require clarification.

Required CI, deploy artifacts, live read-only checks and tenant telemetry searches are independent post-implementation evidence. No customer task mutations were used for verification.
